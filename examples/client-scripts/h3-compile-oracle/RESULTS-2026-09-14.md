# Single-H100 compilation results — 2026-09-14 UTC

Compilation produced no useful speedup on the current optimized H3 path:
**892.606 seconds eager versus 893.163 seconds compiled** for a standard
30-step, requested 15-second video. The 0.557-second difference is 0.062%; one
full generation per arm does not establish a statistical regression. MP4,
continuation PNG, pre-encode video pixels, and audio samples were byte-identical.
Full AV decoding passed.

## Measurement

All requests used ordinary default-home `cozy run` on one H100 80GB HBM3. H3
1.14.3 serving files, checkpoint, seed 7101, jazz-stage prompt, precision,
attention route, and existing Runtime fusions stayed fixed. The output contains
362 frames at 1344 × 768, 24 fps, with stereo audio. See [README.md](README.md)
for the exact input and preparation commands.

The first compiled request unexpectedly received a replacement executor, so it

and finalization. A final eager profile with the same helper/PID measures a
28.849561-second first step, consistent with the earlier 28.812510-second sample.

## Compiler cost and useful findings

Cold regional compilation measured 5.092 seconds in the outer compiler metric,
including 2.245 seconds in the backend, with a 33.557-second first step. It
verified an empty Inductor cache while retaining existing Runtime Triton kernels.
Max-autotune and broader DiT configurations measured outer compiler times of
272.539 and 36.913 seconds respectively; both could reuse disk caches. These
metrics are nested and can overlap queued GPU work; do not add their categories.

All settings use `fullgraph=False`, `dynamic=False`, and disabled CUDA graphs.
Triton/CUDA-stream boundaries leave graph breaks. Regional compilation captures
17 fragments on the first scheduler step and 22 after the second; broader DiT
compilation captures 44 fragments. Warm profile graph counts stay unchanged,
and no recompile-limit fallback is recorded.

Equal first-step CUDA profiles show why latency barely changes:

- All strategies retain the same 52 BF16 FlashAttention 3 calls, 313 scaled
  nvjet GEMM calls, and 300 existing Runtime fusion calls. Attention accounts
  for 85.55% of eager GPU kernel duration; scaled GEMM accounts for 11.00%.
- Regional compilation reduces launches from 1,375 to 1,325. Table fusion
  replaces 150 tiny launches with 50 and saves only 0.306 milliseconds per step.
- Compilation also turns disabled dropout into 50 activation clones, adding
  38.507 milliseconds per step. Removing these would repair a compiled-path
  cost; the current eager path already avoids it.
- Broader compilation reduces launches to 1,305 by fusing small packing,
  modulation, and refiner operations. Attention remains external and unchanged.
  Profiled steps are 28.813 seconds eager, 28.865 regional, 28.970 max-autotune,
  and 28.895 broader DiT. These are individual instrumented samples.

The evidence supports investigating attention implementations next. It does
not justify a production compile-at-boot path or another tiny table kernel.
