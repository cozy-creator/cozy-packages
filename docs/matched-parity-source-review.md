# Complete SDXL/Anima parity source pass

Tracker #319/#324, production PR #390. This is source evidence against Comfy
20ca544ee0436721d8eb5f544665e490609f72c8 and actual Diffusers 0.40.0. API owner
independently reviewed the SDXL conditioning, boundary casts and decoder/output
findings. Source/CPU evidence does not prove full-network, GPU or image parity.

| Stage | Source result and remaining gate |
| --- | --- |
| Model values | Complete logical values remain unproven. The supported CPU inventory job hashes every admitted native part with a one MiB buffer. Only plain values normalize to dense tensor inventories; encoded values refuse until their logical export is reviewed. Include both encoders, conditioner and VAE. |
| SDXL tokenizer | Both towers use CLIP vocabulary/merges, start 49406 / end 49407, length 77; first tower pads EOS and second pads zero. Cozy truncates one section; stock Comfy parses prompt weights and can emit multiple sections. Actual declared short plain inputs need CPU token equality. Actual model asset overrides must be inspected separately from bundled assets. |
| SDXL encoder compute | CONFIRMED SOURCE difference: Comfy `SDClipModel.forward` requests FP32, embeds/position addition produce FP32, and `manual_cast` operations cast weights to activation dtype. Stored FP16 weights do not imply FP16 compute. Cozy's initial candidate constructs FP16 towers. Production extension constructs FP32 towers and casts conditioning at the leased UNet boundary. |
| SDXL hidden/pool | Both select unnormalized penultimate hidden states from both towers and the second tower's projected EOS pool. Comfy selects the first EOS through valid-token count; Transformers' legacy EOS 2 branch selects the largest token ID, which is EOS 49407 for these vocabularies. Actual tiny shared-weight forward and literal token checks remain required. |
| SDXL size conditioning | Both represent original 1024², crop 0/0 and target 1024². Comfy derives width/height from latent geometry; Cozy authors the same six time IDs. Sinusoidal time projection is FP32 before the FP16 UNet boundary. Probe actual values; do not infer from the node name. |
| Anima tokenizer | Qwen3 and T5 tokenizer algorithms/assets need literal ID proof. Cozy truncates to 512; Comfy permits longer inputs and T5 prompt weighting. These are conditional differences outside a short plain cohort. Empty Qwen prompt handling also differs (Cozy zero token/mask versus Comfy minimum pad token). No blanket prompt-equivalence claim. |
| Anima encoder/masks | Qwen residual compute remains BF16; stock wrapper widens its output to FP32 before the conditioner casts back to BF16. That widening is harmless for BF16 values. Cozy passes source/target masks and zeros masked states; Comfy's adapter does not pass those masks. Single nonempty unpadded requests have all-valid masks; empty/padded cases need separate proof. |
| Anima conditioner | Both use the Qwen-to-learned-T5 adapter, RMS/MLP/rotary operations and zero padding to 512 tokens. Actual mask/backend behavior and complete adapter values remain unproven. An all-valid mask and no mask have the same equation but can choose different kernels. |
| Denoiser input | Comfy retains FP32 sampler state and casts network latents/context/extra conditions to its actual inference dtype. Candidate SDXL retains FP32 state but must explicitly cast prompt, pool and time IDs as well as latents to the leased UNet dtype. Anima's maintained before-denoiser block casts only network latents to BF16. Actual Comfy inference dtype must be observed. |
| Denoiser timestep | SDXL uses matching integer training indices on the leading 20-step grid; index equality still needs a direct CPU assertion. Anima stock uses multiplier1 and FP32 normalized sigma. Initial Diffusers block cast t to BF16 before dividing 1000; candidate maintained subclass preserves FP32, with all 30 values/embedding inputs checked in CPU proof. |
| Guidance | Declared SDXL CFG 7 and Anima CFG 4.5/full interval use both branches in FP32. Comfy may batch or split branches under memory pressure; Cozy SDXL batches two and Anima runs sequentially. Batch/kernel effects require real output tolerance. The public Cozy `guidance <= 1` conditional-only behavior is retained and is not asserted equivalent to arbitrary stock CFG values. |
| Schedule/noise | Measured sigma differences: SDXL ddim_uniform 4.77e-6; Anima normal 1.19e-7. Initial installed SDXL leading noise scale differed 0.04524994. Candidate CPU-seeded FP32 noise and EPS below/at/above-maximum scaling are proven on the tested cases. Flow starts at sigma 1 with zero latent. Eight actual CPU noise cases match stock exactly. |
| Euler arithmetic | Both retain FP32 state and predictions after network output casting. EPS-CFG versus denoised-CFG expression order is algebraically equivalent, not bit-identical. Twelve actual 20/30-step synthetic schedules differ by at most 7.72e-7 scaled. This bound is observed CPU evidence, not a bound for a real network. |
| Latent inverse scaling | CONFIRMED SOURCE differences: stock unscales sampler outputs in FP32 before VAE cast. Initial Cozy SDXL casts first then divides 0.13025; Diffusers Anima casts first, divides by a BF16 reciprocal std and adds BF16 mean. Production extension performs SDXL divide or Anima std multiplication/mean addition in FP32, then casts once to the actual VAE dtype. Actual constants and method arguments need CPU proof. |
| VAE precision/strategy | GPU SDXL chooses native BF16 or FP32 for force_upcast; Anima constructs BF16 VAE. Stock VAE dtype is selected by actual device/flags and must be recorded. Whole-frame, tile geometry and fallback differ and need independently quality-qualified disclosure; there is no geometry-equality claim. Stock 512 tiled SDXL at 1.5 GiB remains 30 dB/unqualified. |
| VAE operations | Runtime de40 still applies Qwen `fast_decode`: single-frame temporal last tap, no lone-frame cache and BF16 `F.normalize`. Stock Comfy Wan uses the same normalize equation. Reserved independent PR #387 instead preserves stock Diffusers' FP32 quotient and must not be silently treated as this policy's proof. Exact effective SDK/package roots and attention implementation need observation. |
| Attention/math flags | Both can use PyTorch SDPA, but Runtime selects per-site kernels and Comfy has public backend flags. BF16/FP16 activation labels alone do not prove matching attention precision, TF32, reduction or cuDNN settings. Record effective per-site kernel/precision and global math flags, then compare actual denoiser/conditioning outputs. Backend names may differ only with reviewed equations and qualified quality. |
| Final pixels/container | CONFIRMED SOURCE difference: stock copies VAE output to default FP32 intermediate, then add 1 / div 2/clamp and multiplies 255 before uint8 truncation. Initial Cozy paths normalized/multiplied at decoder dtype. Extension widens before normalization. Both truncate, rather than round, to uint8. Cozy WebP is explicitly lossless/exact in Runtime; stock PNG differs only in container/compression once RGB agrees. File bytes and delivery time remain observed independently. |

The remaining small CPU proof executes actual Comfy/Transformers tiny CLIP on
shared half-representable weights, all 68 declared tokenizer inputs, actual
production boundary methods and actual latent/image formulas at authored geometry.
It uses no model weights, CUDA or precomputed conditioning in production. The
shared CPU lock currently belongs to the independent VAE diagnostic, so queued
work remains pending without a time-based kill. Full tensor export, actual model
assets, real conditioning/network arguments, new same-engine controls, all
pressure cells and paired controller-output timings still block a win.
