# serverless-endpoints (v2)

First-party endpoint packages authored against `cozy_runtime.author`. The tracker is the design
authority; this repository contains endpoint schemas, model-specific computation, deterministic
conformance drivers, and default development bindings.

## Layout

| path | responsibility |
|---|---|
| `h3/` | MiniMax H3 FL2VA and Ref2VA FULL reference endpoint (se-012) |
| `sdxl/` | SDXL text-to-image endpoint (se-008) |
| `quality-judge/` | evaluation actions (ev-003) |
| `*/endpoint.toml` | default model selection; deployment bindings remain authoritative |
| `*/endpoint.descriptor.json` | committed public surface generated by Cozy Runtime |
| `scripts/fence.py` | structural ownership and deletion fences |
| `scripts/*-conform.py` | deterministic contract and numerical red arms |
| `scripts/*-live.py` | installed-artifact and production proof drivers |

## Boundaries

- Code states capability; bindings state selection. Endpoint modules contain no repository,
  checkpoint, release, or download identity.
- Runtime alone hydrates and decodes typed assets, places model components, and encodes outputs.
  Endpoint code receives public decoded values and never opens a path, URL, container, or packet.
- Model code owns model-specific normalization, conditioning, schedules, inference, and output
  semantics. It does not own storage, networking, device placement, offload, or quantization.
- Module scope stays light. `cozy-runtime describe` must work without Torch, model libraries, a
  GPU, or weights.
- Community implementations are research evidence only. No community node, graph, prompt parser,
  checkpoint reader, or serving dependency is present here.

## MiniMax H3

The H3 package exposes exactly two actions:

- `first_last_frame_to_video` uses `Fl2VAModel` and accepts zero, first, last, or both keyframes.
- `reference_media_to_video` uses `Ref2VAModel` and accepts one ordered tagged list of image,
  video, and standalone-audio references.

Both actions use the official Diffusers MiniMax H3 implementation and the same shared text encoder,
video VAE, audio VAE, and schedulers. Each thin model role constructs only its task transformer:
`transformer` for FL2VA or `transformer_ref` for Ref2VA. The interim community curve architecture
was deleted instead of retained as a second graph.

The launch cell is part of the release, not request policy: 345 frames at 24 fps, with the official
30-point sigma grid including terminal zero and exactly 29 transformer evaluations. Duration,
frame-count, step-count, task-selector, graph-selector, and AdaLN-mode request fields are absent.
This reference release supports only the official FULL AdaLN computation. The later production
release will use exact precomputed tables and omit replaced AdaLN weights and computation entirely;
there is no runtime toggle between the two.

Ref2VA preserves request order and enforces the official product bounds: at most 9 images, 3 videos,
3 standalone audio clips, and 12 entries total. Video and audio clips are 2–15 seconds, with at most
15 seconds per modality in aggregate. A video's embedded soundtrack belongs to that video and does
not consume the standalone-audio count. Standalone audio cannot be the only reference modality.

Both actions return one muxed MP4 and one lossless PNG continuation frame. The continuation frame is
captured from the final decoded RGB8 frame before MP4 encoding; its stored-byte digest and source
RGB digest are separate identities.

### Release closure

The endpoint lock pins released Diffusers, Transformers, and the CUDA 12.9 Torch family. Until the
first-party packages are published, exact Cozy Runtime and Cozy Eval wheels are committed as
vendored build inputs. Tokenizer and processor configuration has one authority: the exact bound
model artifact. The endpoint ships no duplicate copy and performs no model-hub lookup. See
`h3/VENDORED.md` for source SHAs, stored-byte hashes, and reproduction commands.

The lock is necessary but not sufficient for a production claim. Promotion also requires a
platform-specific verified wheel set, an offline empty-environment install receipt, codec census,
the uniform dual FULL model snapshot, and output proof on the admitted provider GPU.

### Long-form video

H3 remains a single-shot endpoint. A roughly two-minute result is eight durable ordinary H3 shots:
one Ref2VA shot followed by seven FL2VA shots whose first frame is the prior shot's exact
`continuation_frame`. A separate weightless assembler removes the seven replayed handoff frames and
performs one Runtime-owned streaming encode/mux. Creator owns the durable nine-step workflow.

This keeps model inference, media transformation, and lifecycle recovery separate. There is no
`generate_long`, endpoint loop, hidden child invocation, community interpolation path, or second
workflow ledger in this repository.

## Local verification

The cheap gates require no weights or GPU:

```bash
uv venv --python 3.13 .venv-check
uv pip install --python .venv-check/bin/python \
  h3/vendor/cozy_runtime-0.0.1-py3-none-any.whl \
  msgspec protobuf grpcio av mypy ruff

.venv-check/bin/python scripts/fence.py
.venv-check/bin/python -m mypy
.venv-check/bin/ruff check h3/ quality-judge/ sdxl/ scripts/
.venv-check/bin/cozy-runtime describe --dir h3 --check
.venv-check/bin/cozy-runtime describe --dir quality-judge --check
```

The H3 project environment is reproduced only from its committed lock:

```bash
cd h3
uv sync --locked
uv run ../scripts/h3-conform.py
```

`scripts/h3-live.py` is the final installed-artifact/RunPod probe. A green static or CPU gate does
not prove video generation; both public actions must still produce viewed and listened outputs from
the exact released artifact on the exact read-back accelerator identity.
